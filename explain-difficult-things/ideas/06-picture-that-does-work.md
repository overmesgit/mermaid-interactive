# Draw a picture that does work

Add a diagram only when it does something the words cannot, and shape it like the idea.

## Why

A diagram helps because it puts things that are used together in the same place, so the eye finds them without searching, and some conclusions can be seen instead of worked out. That only happens if the diagram is built for it. A diagram that repeats the text, or that the reader cannot read, adds work instead of saving it.

## How

- Before drawing, say what the picture is for: show something the text cannot, block a likely misreading, or let the reader compare two views.
- Match the shape of the picture to the shape of the idea: a sequence for an order of events, a state diagram for a lifecycle, a graph for dependencies.
- Put the things the reader needs at the same moment next to each other.
- Put the words on the picture or right beside it, not in a distant paragraph.
- Name the parts before showing the process that uses them.
- Cut every box and label that the explanation does not use. Highlight the one that matters now.

## Example

To explain why a cancelled bookshop order never reaches the warehouse, the order state diagram shows it at a glance: Cancelled has no arrow to Fulfilling. A paragraph listing every state and transition would make the reader build that picture in their head.

## Watch out

- A diagram only helps a reader who knows how to read that kind of diagram. Explain the notation if it is unusual.
- Fine differences (exact angles, small size changes) are not seen. Make the important difference large.
- A second picture of the same thing costs the reader a translation. Add it only if it does a different job.

Based on: Larkin and Simon on diagrams; Tversky's congruence and apprehension principles; Ainsworth's DeFT; Mayer's multimedia principles.
