# Explain clearly

An explanation can be correct and still lose its reader: it opens on a detail before the reader knows the system, says the same thing in three places, or draws a picture the text never points at. These rules come from readers who got lost in real lessons, and each one says how to avoid one way of losing them.

This skill covers what to say and draw. The interactive-explainer skill covers how to build the page. Use both together: this one to plan, write, and review, that one to write the content file and build it.

The rules are in [references/rules.md](references/rules.md). Read it before planning. Each rule has a **Rule**, an **Apply when**, and, where the tool helps, a **How**.

## Plan

1. Find the key points, following Give the key points the most care: the few points that most decide how the system behaves.
2. Lay out the lesson with The order of ideas: the whole system first, then the problem, or the diff for a change, then the plan. Then check that each step stands only on what the steps before it showed.
3. For each key point, decide its picture: an everyday analogy where one fits well, or a simple model. Then pick the example values the lesson will use in every step.

## Write and draw

Write each step with its facts first, then the picture, then the real why. Follow the Sentences rules as you write. For each diagram, follow What the diagram draws and Color.

## Review

Before handing over, read every rule's **Apply when**. For each rule that applies to the lesson, check the lesson against it and fix what breaks it. The rules that say "Always" apply to every lesson.
